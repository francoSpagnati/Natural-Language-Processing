# --- Step 0: esplorazione dati ------------------------------------------------
# Nessuna dipendenza esterna. Il caricamento usa solo `json`, le sonde `re`, i
# test `unittest`: tutto libreria standard. Restare a zero dipendenze in questa
# fase e' voluto, cosi' l'esplorazione e' riproducibile ovunque senza installare
# nulla e senza che una versione di libreria possa alterare i risultati.
#
# --- Step 1: schema dello stato paziente -------------------------------------
# Pydantic valida i dati invece di limitarsi a descriverli, genera lo JSON
# Schema dei file intermedi, ed e' comunque richiesto dallo step 10 per il tool
# MCP: definire lo schema altrove significherebbe mantenerne due versioni.
pydantic>=2.0

# --- Step 3: pipeline A deterministica ---------------------------------------
# PhraseMatcher confronta token e non caratteri, quindi non trova "ictus" dentro
# "peri-ictus", e scala su ~10.000 forme dove un'alternanza di regex no. Il
# documento tokenizzato serve comunque alla logica di negazione, che ragiona su
# frasi e distanze in token.
#   Richiede anche il modello italiano:
#   python3 -m spacy download it_core_news_sm
spacy>=3.7

# --- Step 4: pipeline B (estrazione con LLM) ---------------------------------

# `urllib` della libreria standard (vedi src/llm_backend.py): il protocollo e'
# una singola POST JSON, e tenerla esplicita mantiene visibile nel codice il
# formato del messaggio invece di nasconderlo dentro un SDK, senza legare la
# riproducibilita' dei risultati alla versione di un pacchetto.
